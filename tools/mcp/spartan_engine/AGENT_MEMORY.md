# Spartan Agent Memory

This file is shared memory for agents working on Spartan Engine. Keep it short, factual, and useful for future runs. Replace wrong notes instead of piling corrections on top of them. One note stays under 1200 chars; when the file is full the oldest Lessons move to AGENT_MEMORY_ARCHIVE.md (search it with agent_memory_read {archive_query}).

## Engine Facts
- Engine MCP commands run on the engine main thread at the start of the frame; request ids are echoed in responses and debug logs. Mutating scene tools require edit mode.
- `context_snapshot` is the fastest first read (status, world, selection, camera). `async_task_start`/`async_task_get` run long tools in the background.
- `engine_command {command, args}` forwards any native bridge command. Use it for commands added to the engine after the MCP server started, or args a dedicated tool lacks. Tool inputs pass unknown args through, so an older server no longer strips new engine args. New dedicated tools still appear only after Cursor respawns the server: change its env (e.g. SPARTAN_MCP_REVISION) in ~/.cursor/mcp.json.
- `shader_reload` hot reloads shaders: it recompiles every shader whose .hlsl or include differs on disk from what it was compiled from (`name` filters, `force` recompiles matches). Compiles run in the background; call again until `compiling` is 0, then check `failed` and `console_read`. Edit the repo's data/shaders (binaries/data/shaders is setup's fallback copy, not what runs).
- `component_get` exposes properties, raw members and metadata (ranges, units, enums, side effects); `component_set`/`component_set_batch` write them, `component_action` runs component methods (terrain generate, spline road mesh, particle presets, light fit_to_mesh...).
- `terrain_scatter_get` / `terrain_scatter_set {layer, values}` read and edit terrain scatter layers (vegetation, rocks, grass) with the world file's <layer> attribute names. Grass/detail update instantly; mesh layers rescatter in the background (poll `mesh_rescatter_running`) and every mesh layer re-rolls.
- Resources: `resource_list/load/reload/save/remove`, `material_get`, `material_create`. `world_save` prunes unreferenced files from the world resources directory; `world_resources_clean` returns a receipt.
- `camera_set_view` works in edit mode and paused play. In play mode with the first person camera it teleports the player: position is the eye, the controller capsule follows. `viewport_frame` frames descendant bounds from a named view.
- `screenshot_take` returns the image; `{ui:true}` (cvar r.screenshot_ui) includes the editor UI of the main viewport. The MCP returns a 1024 px preview; the full PNG is under binaries/project/mcp/blockout/thumbnails.
- Cars in play mode: `vehicle_list/get`, `vehicle_enter` (mcp pedal ownership), `vehicle_set_input`, `vehicle_shift`, `vehicle_set_view`, `vehicle_reset`, `vehicle_exit`, `vehicle_set_tire_pressure {psi|bar}`, `vehicle_telemetry` (car_telemetry.csv in the working directory). Pressure is stored in bar, psi is display only.
- Sequencer: `sequencer_get/set/playback`, `sequencer_event_*`, `sequencer_spline_*`, `sequencer_drive_*`, `sequencer_render`; state auto-saves to `sequencer_<world>.xml` under the project directory. Playback in play mode holds the timeline (up to 10 s) until drive cars are staged, so play started in edit or preview mode no longer leaves cars parked.
- `spline_query` (no args) projects every camera onto the followed spline and returns `arc_distance` and exact `pass_time_seconds` (followers move at constant world speed). `spline_distribute` respaces spline cameras evenly; `edge_offset` 2 clears the asphalt, use 1 on roads with side walls (plan.world).
- Glass materials use `color_a`, `ior`, `absorption`, `thickness`; `transmission`/`transparency` alias inverted `color_a`.
- Bridge aliases: `entity_describe` = `entity_get`, `entity_list_children`, `agent_memory_update` = append, `resource_read` = `material_get`/`resource_list`, `prefab_create` = `prefab_save`.
- cvar_set blocks only r.resolution_scale, r.hdr and r.antialiasing_upsampling. Render cvars persist to binaries/spartan.xml, so restore what you change. debug.* cvars are startup only (edit spartan.xml and restart).

## Good Agent Strategies
- Use `search_capabilities` / `get_capability_details` before guessing tool names; `debug_log_read` after failures.
- Resolve targets with `entity_resolve` before mutating; read world transforms from it.
- Prefer native tools over Lua: batch creation (`entity_create_primitive_batch`, `mesh_generate_batch`, `compound_create`), `entity_set_transform_batch`, `selection_update`, `entity_clone`, prefab tools, `material_set_property`/`material_set_texture`, `undo_redo`.
- `material_textured_create` is the one call for a real surface (material plus color, normal and packed maps). `texture_generate` layers: fill, gradients, noise, checker, stripes, bricks, tiles, spots, scratches, shape, text; `relief` drives normals. Tune tiling textures from the reported contrast and `seam_error`; labels and decals set `seamless` false.
- Parametric shapes: box, plane, sphere, ellipsoid, hemisphere, cylinder, cone, frustum, arc, sector, disk, ring, tube, lofts, sweeps and architectural shapes; see `spartan://engine/parametric-modeling`.
- Use `entity_create_light` for every light. Intensity is lux for directional, lumens otherwise; visible defaults point/spot 8500, area 12000, directional 120000. `lights_calibrate` fixes existing lights in one call.
- City work: `city_blockout`/`district_blockout` for massing; roads from `world_landmarks` plus an arterial that skirts districts, `spline_junction`, `spline_decorate`; `spline_reroute` fixes a road through buildings and keeps its lights/cameras. Never hand-build `spline_point_*` children.
- Blockouts: resolve or create the parent at a `world_raycast` ground point, one batch call, `entity_create_light`. Agents that fall into Lua API probing fail (and exploratory probing has crashed the engine).
- Before rebuilding geometry that should keep its look, `entity_render_materials` the target and reuse the materials.
- Focused reusable assets: one construction pass, one game-ready pass, one catalog upsert, one Asset Viewer screenshot. No part or triangle cap; hero bodies use dense lofts (24 to 64 points, 12 to 32 stations); merge same-material geometry, put fasteners and wear into textures.
- To drive a car: `engine_set_mode` play, `vehicle_enter`, hold `vehicle_set_input`, then `vehicle_telemetry`.
- Sync sequencer cuts to a follower: set its speed, `spline_query`, place each cut midway between consecutive pass times.
- Routing: construction prompts (level, rooms, backrooms) are live scene edits; simple deletes go to `entity_delete`, delete-plus-rebuild does not; `physics <primitive>` means dynamic unless static is asked for; prompt classification lives only in `route_intent`.

## Gotchas
- World loading blocks most commands. Never world_load twice in one engine session (GPU memory blows up and frames take seconds); restart the engine instead. First frames after a load build BLAS for seconds.
- Several agents share port 47791 and the development exe, and instances get closed or replaced. The exe is locked while any instance runs: build a private exe with /p:TargetName=<name> and /p:IntDir=binaries\obj_<name>\x64\development\ (seed it by copying binaries\obj\x64\development), run it on another port (spartan_engine_ui is 47792). Never close an instance you did not start.
- Long Lua runs on the main thread, keep it bounded. Lua tables from `World.GetEntities()` and `GetChildren()` are 1-based; prefer `ForEachChild`, never `pairs()` on raw C++ containers. Entity ids exceed Lua number precision: use `World.GetEntityByName` or pass ids as strings.
- Sphere, cylinder and cone primitives have radius 1 (diameter 2x the xz scale); cube and quad are 1 unit. Batch positions are parent-local when `parent_id` is set.
- `detail_pattern_create` slats: `size` is one slat, total span is `count * spacing`.
- `spline_junction` snaps nearest endpoints only; for a mid-route T split the arterial into two legs ending at the junction.
- `mesh_generate`: `mirror_axis` reflects in place, `mirror_copy: true` keeps both halves. Box UV normalizes over the whole mesh, one `uv_scale` cannot serve faces with very different extents. Rounded boxes map each face to full 0-1 UV; use a raw mesh UV island for unique art. `revolved_profile` normals follow profile order (bottom to top faces out). Closed profiles are listed once, counter clockwise; fix the one problem a rejection names.
- `material_textured_create` returns `material_path`, use it for later calls; `height` is texture pixels, `displacement_height` is material displacement. Attaching roughness/metalness maps sets those scalars to 1 by design (the map carries the finish). Glazed ceramic, car paint and varnish need `clearcoat` 1, `clearcoat_roughness` 0.04, `ior` 1.5 (reference: `Material::ApplySurfacePreset`).
- `texture_generate` at a loaded path writes to the next free suffix and rebinds; read `path` from the response. `material_set` color_r/g/b only darken; to lighten, generate textures at a new path with `material_path` set.
- MCP output lives under project/mcp/blockout (meshes, materials, textures, thumbnails, catalog); never `<world>_resources`. project/mcp/library stays empty until assets are promoted. Text layers use data/fonts (latin only).
- ImGui windows with `NoBringToFrontOnFocus` draw behind the dockspace; use `NoInputs` or `GetForegroundDrawList()` for overlays. No MCP tool clicks, expands headers or opens menus, so collapsed UI and popups cannot be verified visually.
- The performance overlay (r.performance_metrics 1 full, 2 compact) is drawn by the renderer text pass, so it appears in screenshots. Screenshots freeze while play is paused or the window is minimized (frame_number stops).
- `asset_viewer_preview_path` takes library/blockout .mesh, material and texture paths only; for models (.glb) preview an entity that uses them with `asset_viewer_preview_entity`.
- ModelImporter reuses `<model_dir>/<snake_case material>.xml` and packed textures are cached in memory: after changing a GLB material's textures, rename the material or delete that xml and restart. Engine glb needs external texture uris (export GLTF_SEPARATE, pack json+bin yourself).
- Compressed texture mips are cached in `<world>_resources/generated_cache/texture_mips`; bump the bake_key version after encoder changes. Opaque colour maps use GPU BC7 (BC1 made purple/teal blotches). Empty texels in baked atlases default to 0 (roughness 0 mirror), fill them with base material values.
- Adding a StructuredBuffer or ConstantBuffer to a pipeline raises its Vulkan dynamic offset count; the cap is rhi_max_dynamic_offsets (16, RHI_Definitions.h), overflow crashed in RHI_CommandList::PreDraw.
- Crash dumps land in %LOCALAPPDATA%\CrashDumps; copy cdb to %TEMP% and run `cdb -z dump -y binaries -c ".ecxr; kn 40; q"`. The PowerShell tool can drop formatted object output; emit strings (ForEach-Object or Out-String) before concluding nothing was found.
- Worlds sit ~7 km from origin: rasterize camera relative (view_projection_relative, transform_to_clip_space) and build views with CreateLookToLH.
- Static collision (meshes, garage floors, props) only exists within 40-80 m of the active camera (Physics::TickDistanceActivation, outside_collision_prepare_range). Entering play with the editor camera far from a car drops it through the floor: plan.world's player_car falls through the garage (6213,13.5,-2858) when play starts from the road view. Frame the car first or `vehicle_reset` after moving the camera there. Do not teleport the player onto live traffic lanes (plan.world road z -3885): traffic knocks the capsule tens of metres; use the field at (4600,5,-3960).

## Advice To Maintainers
- Add native engine tools when agents repeatedly need the same multi-step command sequence; keep MCP schemas close to engine metadata.
- Log only unknown commands as capability gaps; connection and command timeouts are bridge-health failures. Never store prompt snippets here.
- Open gaps: a second play-mode entry per session has hit VK_ERROR_DEVICE_LOST during car renders; a second world_load per session blows up GPU memory; no MCP tool captures audio; no MCP tool clicks editor UI; the Memory Viewer CSV export is button only; ReSTIR hit shaders do not apply puddles (RT reflections do, via common_ray_surface.hlsl); restir direct lacks cloud shadows, ocean transmission and non-TLAS grass contact shadows.

## Memory
- Measuring memory: log.txt logs 'Cpu memory (world ready|steady)', 'Gpu memory (...)' (per kind, top names and textures, VMA heaps used vs committed) and 'Gpu geometry (world ready)'. The Windows counter '\GPU Process Memory(pid_N*)\Dedicated Usage' is ground truth for VRAM. SPARTAN_HEAP_CENSUS=1 enables a callstack heap census. plan.world after 2026-09 fixes: peak VRAM ~6.8 GiB, CPU ~6.6 GiB.
- VRAM rules: guardrail W-beams are GPU instances of one 4 m module, never baked per chunk. Uncompacted BLAS and scratch use a transient VMA pool; the initial BLAS burst compacts as builds retire. GeometryBuffer keeps no CPU mirror (Mesh::SetCpuGeometrySource restores lazily). Physics cooks with a 1 mm weld (1 cm folded 3 mm sheets). Remaining candidate: 4 per-frame copies of meshlet_instances/visible_triangles/surviving_instances (~1 GB).

## Rendering
- 2026-09-28 push constants: every pass reads named slots, e.g. pass_float(pass_fog::mist_density) in HLSL and m_pcb_pass_cpu.set(pass_fog::mist_density, x) in C++. The slot tables live in data/shaders/shared_buffers.h, 20 scalar slots after the 16 byte header, so the push constant size never changes (Vulkan reflection and the D3D12 root constant count stay valid). Integers go through set(slot, uint32_t) and are read with pass_uint, which is bit exact; bools use pass_bool; int or size_t arguments are ambiguous on purpose, so cast. Add new params as a namespace in shared_buffers.h, never as raw buffer_pass.values reads. Fresh plan.world loads lack the dense dry grass right of the road viewpoint (4560,7.5,-3885), so compare fresh loads with fresh loads (rhi_baseline_fresh_road.png).
- Volume components (e.g. the 76 soundscape regions in plan.world) draw their boxes/audio polygons in edit mode; toggle with cvar `r.volumes` (Debug tab > Volumes), separate from `r.aabb` (render + light bounds). Light flare cvars (r.light_flares*) were removed; flare parameters are hardcoded in Pass_LightFlares and Renderer.cpp.
- 2026-09-29 RT reflections + clearcoat: the tracer, nrd_pack and reflections_apply trace/weigh only the coat lobe (roughness lerped to clearcoat_roughness, F0 lerped to 0.04), and light_image_based zeroed specular ibl when r.ray_traced_reflections is on, so coated metals (LaFerrari logos/badges metal 0.91 coat 1, headlight chrome, carbon) lost their whole base lobe and went black. Fix: light_image_based keeps specular_ibl * clearcoat for opaque pixels under RT (base lobe on ibl, coat lobe traced), matching light.hlsl which adds both lobes. The spawned car uses generated materials named car_<id>_<src id>_<role> (body_paint, main_glass...), not the model xml; material_get those. RT glass reading greyer than non-RT is expected: rays hit the sunlit asphalt, non-RT samples the dark lower sky.
- 2026-09-29 RT reflection ownership: get_rt_reflection_weight(reflection_roughness) in common.hlsl (fade 0.8..0.9, past the tracer's alpha 0.6 cap at roughness ~0.88) is the single source for how much of the specular lobe RT owns. reflections_trace skips where it is 0, reflections_apply scales the traced lobe by it, light_image_based keeps specular_ibl * (1 - w * (1 - coat)) (coat only for opaque). Before this, trace skipped at 0.9 while apply faded to 1.0 and ibl zeroed all specular, so roughness >= ~0.85 surfaces (asphalt, concrete, grass, rough metals) had no specular with RT on (grazing asphalt ~3% darker). Change any of these thresholds only through that function. Auto exposure takes ~10 s to settle after a big view change; wait before comparing screenshots.
- 2026-09-29 RT reflection hits share one path: common_ray_surface.hlsl (hit reconstruction with ray cone mips, road/decals/ground_water_apply/rain_apply, secondary shading) + common_radiance_cache.hlsl (world hash grid, u70 RWStructuredBuffer radiance_cache, 1 in 4 pixels trace a bounce to feed it). reflections_shade adds clearcoat/sheen at hits, top-2 exact + reservoir local lights, a second mirror bounce for roughness < 0.35, froxel fog along the ray; misses take the camera's froxel column (sample_fog_volume) when the direction is on screen. reflections_apply traces glass refraction (ray_surface_shade_secondary) when r.ray_traced_reflections is on. Split-sum multiscatter lives in brdf.hlsl compute_multiscatter_energy_split_sum. Cost at 1920x968 car_playground: trace 0.34, shade 1.08, denoise 0.62, apply 0.13 ms. Wet overcast ground reads navy in both RT and IBL because the raw skysphere is darker than the mist-lit sky the camera sees; not an RT bug. Bugs found by the user and fixed: (1) any lobe left on the sky probe under RT shows the outdoor sky indoors (garage paint washed pale blue), so reflections_apply lights BOTH base and coat with the one traced ray and ibl keeps only the rough (1 - weight) share; (2) hit shading must multiply the sun by cloud_shadow_sample (tex6 = cloud_shadow in shade/apply) or overcast scenes light reflected surfaces at full sun (glowing red self reflections in rain); (3) never pick one light uniformly and scale by light_count at hits (plan.world has 207 lights), stream all in range lights through a weighted pick. Test windows: my window gets minimized by the user and stray keys move the camera when it has focus; ShowWindow(SW_SHOWNOACTIVATE) + SetWindowPos(HWND_BOTTOM) keeps it rendering unfocused.

## Validation and builds
- Vulkan: compute-queue barriers must not use FRAGMENT_SHADER stages (as_reader_stages in Vulkan_AccelerationStructure.cpp); depth clears are graphics-queue only (depth_previous is cleared in Pass_Depth_Prepass). VVL 1.4.341 GPU-AV falsely rejects compacted BLAS (VUID-12281) and nulls those TLAS instances, making GPU-AV frames washed-out and shadowless; disabled via gpuav_acceleration_structures_builds=false in validation_layer::get_settings. If a validated frame differs from a normal one, suspect the layer. VK_LAYER_ENABLE_MESSAGE_LIMIT=false shows every message; best-practices noise is intentional. D3D12 GBV works on an empty world but sponza needs >10 min to reach its first frame, so use the debug layer alone for scenes. D3D12 build next to Vulkan: scratch copy of tools/premake.lua with dofile ../tools, location '.', OBJ_DIR ../binaries/obj_d3d12, setup.run() stripped (CRLF-aware regex), then premake5 --file=<scratch>/premake.lua vs2026 d3d12. setup.lua skips identical dll copies. spartan.xml writes and loads every cvar (except r.fog.debug) in commented sections; add new cvars to a section in get_sections (Settings.cpp) or they land in OTHER.

## D3D12 vs Vulkan
- A texture that looks different per backend is usually a missing texture: D3D12 null srv samples black, Vulkan shows the grey '1 m' checkerboard. Check by writing gbuffer albedo from a temporary reflections_apply output and comparing region means (sponza uses manual exposure). Material::PrepareForGpu must not release a cpu-only slot texture that any material samples directly (colour/normal/emission/packed); curtains_metal_door.xml wires the door colour map into metalness. RHI_Shader::ApplyReload must copy m_object_size or D3D12 hot-reload PSOs fail with E_INVALIDARG.
- D3D12 build beside Vulkan: copy tools/premake.lua to a scratch folder at repo depth 1 (dofile ../tools/setup.lua and ../tools/lzma_sdk.lua, OBJ_DIR ../binaries/obj_d3d12, location '.', drop setup.run), run '..\tools\premake5.exe --file=premake.lua vs2026 d3d12', then MSBuild Spartan.vcxproj development x64 (~90 s). Profile one instance at a time; two instances share the GPU. Sponza corridor: D3D12 48.6 fps / 19.6 ms GPU vs Vulkan 53.4 / 18.8; D3D12 g_buffer 2.9 ms vs 0.9, and D3D12 ProduceFrame blocks on cmd_wait_compute and cmd_wait_graphics (~14 ms) so CPU and GPU do not overlap.

- AI steering: pure pursuit weaves at speed. Use curvature feedforward plus damped lateral correction, clamp the demanded curvature to grip/v^2, and learn understeer from yaw rate (the LaFerrari needs ~2x its kinematic steer at the limit; its real grip is ~1.0 g). Scale throttle and brake by the grip left after cornering; braking on understeer drives the car onto the grass.

## Performance
- plan.world perf (RTX 5070 Ti, 1920x968 render): geometry (depth_prepass + g_buffer + scatter) is ~13 ms of ~22 ms in forest views; reflections_shade 1.5-4 ms (garage worst). Proven lever: impostor_screen_fraction in common_culling.hlsl (0.03 -> 0.06 saves ~1.3 ms trees view, ~2.5 ms garage). Impostors looked pale teal because the card has no crown self-occlusion and ambient dominates; fixed with occlusion *= 0.4 for is_impostor in g_buffer.hlsl. Not the cause: roughness/specular AA, albedo mip, normals, RT shadows. Measured non-wins: custom mesh LOD thresholds, VRS (<1 ms), dropping local-light shadow rays in reflections_shade (~0.2 ms). r.resolution_scale is blocked by MCP. A minimized engine window freezes GPU timings and screenshots; ShowWindow(h,4) restores it without taking focus.
