# Spartan Agent Memory

Shared memory for agents working on Spartan Engine. Keep it short, factual and current: replace wrong notes instead of stacking corrections, state the rule and where it lives, drop the story. One note stays under 1200 chars. When the file passes its limit, dated notes move to AGENT_MEMORY_ARCHIVE.md oldest first, then undated topic notes; the first four sections are never archived. Search the archive with agent_memory_read {archive_query} (e.g. "ocean shore", "d3d12 build", "foot ik").

## Engine Facts
- MCP commands run on the engine main thread at the start of the frame; request ids are echoed in responses and debug logs. Mutating scene tools require edit mode. World loading blocks most commands.
- `context_snapshot` is the fastest first read (status, world, selection, camera). `async_task_start`/`async_task_get` run long tools in the background.
- `engine_command {command, args}` forwards any native bridge command, for commands added after the MCP server started. New dedicated tools appear only after Cursor respawns the server (change an env var such as SPARTAN_MCP_REVISION in ~/.cursor/mcp.json).
- `shader_reload` recompiles shaders whose .hlsl or includes changed on disk (`name` filters, `force` recompiles). Compiles run in the background (~129 shaders per edit): wait 15-20 s via screenshot_take wait_ms instead of polling, then check `failed` and `console_read`. Edit the repo's data/shaders, not binaries/data/shaders.
- `component_get` exposes properties, raw members and metadata; `component_set`/`component_set_batch` write them; `component_action` runs component methods (terrain generate, spline road mesh, particle presets, light fit_to_mesh...).
- `terrain_scatter_get` / `terrain_scatter_set {layer, values}` edit scatter layers with the world file's <layer> attribute names. Grass updates instantly; mesh layers rescatter in the background (poll `mesh_rescatter_running`).
- `world_save` prunes unreferenced files from the world resources directory; `world_resources_clean` returns a receipt.
- `camera_set_view` works in edit mode and paused play; in first person play it teleports the player (position is the eye). `viewport_frame` frames descendant bounds from a named view.
- `screenshot_take` returns a 1024 px preview (full PNG under binaries/project/mcp/blockout/thumbnails); `{ui:true}` captures the whole editor window. Screenshots freeze while play is paused or the window is minimized; parallel calls grab the same frame, so shoot series sequentially.
- Cars: `vehicle_list/get/enter/exit`, `vehicle_set_input`, `vehicle_shift`, `vehicle_set_view`, `vehicle_reset`, `vehicle_set_tire_pressure {psi|bar}` (stored in bar), `vehicle_telemetry`, `vehicle_ai`, `vehicle_spectate`. Sequencer: `sequencer_*`, state in `sequencer_<world>.xml` under the project directory.
- `spline_query` (no args) returns each spline camera's `arc_distance` and `pass_time_seconds`; `spline_distribute` respaces cameras (`edge_offset` 2, or 1 on roads with side walls).
- Glass materials use `color_a`, `ior`, `absorption`, `thickness`.
- cvar_set blocks only r.hdr (is_blocked_cvar in McpCommands.cpp); value must be a string. Render cvars persist to binaries/spartan.xml, so restore what you change. debug.* cvars are startup only.
- Editor windows: `engine_command {command:"editor_window"}` lists every editor window; add `title` (e.g. "Renderer Options") + `visible` to show/hide, `width`+`height` to resize, `x`+`y` to move (pixels, relative to the editor window). Keep the window inside the editor: past its edge ImGui spawns a separate OS window that screenshot_take {ui:true} does not capture. Crop the full PNG (thumbnails folder) with System.Drawing to read panel detail; the 1024 px preview is too small for UI review.
- 2026-10-08: Wheel radial motion blur (data/shaders/motion_blur.hlsl, motion_blur_radial_reconstruction). Each wheel pixel's real surface point comes from the depth buffer and is rotated rigidly about the 3D wheel axis (hub + axis + per-frame angle from Renderer::UpdateFrameCb_RadialBlurHubs), sampled over the centered shutter arc +-min(angle*exposure, pi), box weighted, wheel-mask clipped. Do NOT intersect with a single hub plane: tread/sidewall land at the wrong radius and form offset ellipses that leave the wheel. Do NOT always sample a full turn and crossfade by strength: that ghosts a disc over sharp spokes. Visibility only rejects depth steps > 0.1 + 0.5*orbit_radius (back of tire); spokes over brake gaps must be accepted both ways or spoke ghosts remain. Debug: r.motion_blur 2 (red = radial mask, green = has rotation record). Test with vehicle_set_view wheel + vehicle_set_input.

## Good Agent Strategies
- `search_capabilities` / `get_capability_details` before guessing tool names; `debug_log_read` after failures.
- Resolve targets with `entity_resolve` before mutating; read world transforms from it.
- Prefer native tools over Lua: batch creation (`entity_create_primitive_batch`, `mesh_generate_batch`, `compound_create`), `entity_set_transform_batch`, `selection_update`, `entity_clone`, prefab tools, `material_set_property`/`material_set_texture`. Exploratory Lua API probing has crashed the engine.
- `material_textured_create` is the one call for a real surface; `texture_generate` layers: fill, gradients, noise, checker, stripes, bricks, tiles, spots, scratches, shape, text; `relief` drives normals. Tune tiling from the reported contrast and `seam_error`; labels set `seamless` false.
- Parametric shapes: see `spartan://engine/parametric-modeling`. Hero bodies use dense lofts (24-64 points, 12-32 stations); merge same-material geometry, put fasteners and wear into textures.
- `entity_create_light` for every light. Intensity is lux for directional, lumens otherwise; visible defaults point/spot 8500, area 12000, directional 120000. `lights_calibrate` fixes existing lights.
- Cities: `city_blockout`/`district_blockout`, roads from `world_landmarks`, `spline_junction`, `spline_decorate`, `spline_reroute`. Never hand-build `spline_point_*` children.
- Before rebuilding geometry that should keep its look, `entity_render_materials` the target and reuse the materials.
- Sync sequencer cuts to a follower: set its speed, `spline_query`, place each cut midway between pass times.
- Compare fresh world loads with fresh loads (grass and terrain stream differently in long sessions); auto exposure needs ~10 s after a big view change.
- 2026-10-05: Input + headless. input_inject {keys, duration<=60, mouse_delta [x,y] px spread over duration, wheel, release} is a virtual keyboard/mouse (Input::Inject*), never moves the OS cursor. Editor fly camera only moves/looks while Click_Right is held: keys ['Click_Right','W'] + mouse_delta; 0.2 deg/px default (result has degrees_per_pixel). A connected gamepad (DualSense drift) rotates a visible editor camera between shots; headless ignores gamepads and the real mouse. --headless (aliases -headless, --mcp-control --mcp-hidden): hidden window, no editor ui/perf overlay/steam, never writes spartan.xml/editor.ini, logs to binaries/log_headless.txt. headless_start {world} retargets all engine tools to a private instance until headless_stop; engine_quit only closes headless instances. headless_smoke_test runs -ci_test --ci-exit (~25 s). Render.BasicCube already fails headless AND visible (center RGB ~0.26,0.35,0.16), not a headless bug.
- 2026-10-10: Agent toolkit (agent_toolkit.mjs). Session start = engine_ensure {world, mode:'edit'} (launches the newest binaries/ build only if nothing answers, waits for the load, refuses a 2nd world_load unless force_load). engine_wait {until: ready|world|jobs_idle|frames}. tool_batch {steps:[{label,tool,args}]} runs many tools in one call; '$label.path' strings pull earlier results (entity_resolve nests under .entity, entity_find under .matches). Before/after: viewpoint_save named cams (binaries/project/mcp/viewpoints.json, per world), viewpoint_capture {label:'before'} then {label:'after', compare_to:'before'} gives changed_ratio/bounds + diff image; screenshot_compare for any two pngs (threshold ~24 ignores cloud drift). engine_status has minimized; screenshot_take fails fast with window_minimized, window_restore fixes it.
- 2026-10-12 Tree survey: tree_* commands go through engine_command {command, args} until the MCP server respawns. Per species run tree_generate, engine_wait 30 frames, tree_preview_capture {path}, engine_wait 10 frames, in ONE sequential tool_batch; never run two survey batches in parallel, the shared preview mixes captures. Captures land in binaries/project/mcp/library/thumbnails; binaries/obj/make_sheets.ps1 <tag> builds labelled contact sheets. Edit data/trees/species/*.json then tree_species_list {reload:true}, no restart. Bump texture_hash in TreeSpecies.cpp whenever a painter changes. prefab_load ignores position, move the returned root with entity_set_transform {id}.

## Gotchas
- Never world_load twice in one engine session (GPU memory blows up); restart the engine. First frames after a load build BLAS for seconds.
- Agents share port 47791 and the development exe, which is locked while any instance runs. Build a private exe with /p:TargetName=<name> and /p:IntDir=binaries\obj_<name>\x64\development\ (seed from binaries\obj\x64\development), run it on another port (spartan_engine_ui is 47792), delete it when done. Never close an instance you did not start.
- A minimized engine window stops rendering, GPU timings and screenshots; ShowWindow(h, 4) or SW_SHOWNOACTIVATE + SetWindowPos(HWND_BOTTOM) restores it without focus (stray keys move the camera when it has focus). Get-Process cannot see Spartan from the agent shell, use tasklist. There is no MCP quit tool; WM_CLOSE is the graceful exit.
- Lua runs on the main thread, keep it bounded. `World.GetEntities()`/`GetChildren()` are 1-based; prefer `ForEachChild`, never `pairs()` on raw containers. Entity ids exceed Lua number precision: use names or string ids.
- Sphere, cylinder and cone primitives have radius 1; the cone is 2 units tall; cube and quad are 1 unit. Batch positions are parent-local when `parent_id` is set.
- `detail_pattern_create` slats: `size` is one slat, span is `count * spacing`. `spline_junction` snaps nearest endpoints only; split an arterial for a mid-route T.
- `mesh_generate`: `mirror_axis` reflects in place, `mirror_copy: true` keeps both halves. Box UV normalizes over the whole mesh; rounded boxes map each face to 0-1. `revolved_profile` normals follow profile order; closed profiles listed once, counter clockwise.
- `material_textured_create` returns `material_path`; `height` is texture pixels, `displacement_height` is displacement. Roughness/metalness maps set those scalars to 1 by design. Glazed ceramic, car paint, varnish: `clearcoat` 1, `clearcoat_roughness` 0.04, `ior` 1.5.
- `texture_generate` at a loaded path writes the next free suffix; read `path` back. material color_r/g/b only darken; to lighten, generate at a new path.
- MCP output lives under project/mcp/blockout (material_create and mesh_generate always write there), never `<world>_resources`. Read binaries/project/README.md before adding or deleting assets; never add top-level project folders.
- No MCP tool clicks editor UI, injects WASD or OS mouse input, or captures the full audio mix (only the engine synth, via engine_sound_capture): hover, popups and sound mixes need the user.
- Static collision exists only within 40-80 m of the active camera. Entering play with the camera far from a car drops it through the floor: frame the car first or `vehicle_reset`. Keep the player off live traffic lanes.
- `asset_viewer_preview_path` takes library/blockout .mesh, material and texture paths; preview .glb models through an entity with `asset_viewer_preview_entity`. A pending asset_viewer_screenshot can block screenshot_take; `asset_viewer_open {visible:false}` clears it.
- ModelImporter reuses `<model_dir>/<material>.xml` and caches packed textures: rename the material or delete that xml and restart after changing GLB textures. Engine glb needs external texture uris.
- Worlds sit ~7 km from origin: rasterize camera relative and build views with CreateLookToLH.
- Bugs that "a screenshot fixes" are frames-in-flight races (the readback drains the GPU): verify them with the user driving, not captures.
- 2026-10-12 plan.world: terrain_scatter_set on any mesh layer starts a full rescatter (25.8M instances, ~1.4 GB BLAS before compaction) and twice killed the engine within seconds of the geometry buffer rebuild, once with VK_ERROR_DEVICE_LOST, once silently, also with the original olive gltf assets. Avoid rescatter on plan.world until that is fixed. Prefab::SaveToFile skips children not yet in World::GetEntities(), call World::ProcessPendingAdditions() before saving a freshly built hierarchy. Preset bark colours are linear, keep albedo around 0.05-0.25 or trunks read white.

## Advice To Maintainers
- Add native engine tools when agents repeatedly need the same multi-step sequence; keep MCP schemas close to engine metadata. Log only unknown commands as capability gaps.
- Open gaps: a second play-mode entry per session has hit VK_ERROR_DEVICE_LOST during car renders; a second world_load per session blows up GPU memory; no MCP capture of the full audio mix (engine_sound_capture records only the engine synth), UI clicking or camera follow for a moving car; Memory Viewer CSV export is button only; ReSTIR hit shaders do not apply puddles; restir direct lacks cloud shadows, ocean transmission and non-TLAS grass contact shadows; GeometryInfo storage buffer is rewritten at offset 0 per TLAS rebuild while older frames may read it; world_save after play has crashed in Render::UpdateLodIndices on a freed car Mesh (restart before playing again).

## Engine sound
- Match against real recordings (tools/engine_sound/out/reference/laferrari.wav, bin/shift_compare.py). Synth load follows air charge (throttle), not torque. Telemetry recording slows sim ~3x.

## Rendering
- Two-phase occlusion culling (2026-10-10, replaced the occluder pass + refine): Pass_Cull_Early tests last frame's gbuffer_depth_hiz (view_projection_previous), draws the depth prepass, builds gbuffer_depth_hiz_early; Pass_Cull_Late tests that, appends to the same survivor lists, draws only the appended range (cull_phase buffer u88 holds the early ends, args slots 2/3), rebuilds gbuffer_depth_hiz as next frame's history. Instance bits in InstanceVisibility (u89), meshlets replay the history test on tex2. Verify with r.hiz_occlusion 0 vs 1 pixel diffs (settled shots match within the TAA noise floor) and engine_command meshlet_snapshot (late_opaque/alpha_meshlets). Never push cull constants implicitly: every compute pass must call PushConstants.
- GPU-driven main pass (2026-10-10): cvars r.gpu_lod (non-instanced multi-lod draws pick lod in instance_cull, writes DrawData via u87), r.tessellation_gpu_driven (tessellated_cull.hlsl: frustum/distance/hi-z + lod into TessellatedArgs, drawn with DrawIndexedIndirect). All default 1; A/B screenshots on car_playground were pixel-identical to the CPU paths. Testing a private build: headless_start {executable: binaries/<private>.exe, world, timeout_s:600} gives an isolated instance that ignores real input (no camera drift). plan.world failed with 'bad allocation' while other Spartan instances held ~8.5 GB RAM; car_playground loads fine. No world ships tessellated materials (Terrain.cpp forces Tessellation 0); to test, material_set_property tessellation=1 on concrete/kerb_red (unsaved). Pre-existing bug: tessellation on regular meshes without a height map renders them black and flings geometry into the sky, identical in CPU and GPU paths. cvar_set takes value as a string.
- Missing scatter trees/foliage that reappear after nudging the camera = stale CPU cull cache in Render::UpdateFrustumAndDistanceCulling (skips re-test while !visible, out of range and camera moved < 2 m). Bounds changes must reset m_scene->cull_camera_position (done in UpdateAabb and SetBoundingBoxOverride). Quick check: component_get render on a tile child; distance_squared equal to camera-to-origin distance means it was culled against template-local bounds. Wireframe (r.wireframe) shows whether geometry is submitted at all; the MCP cannot display r.meshlet_visualize output.
- Frame generation (r.frame_generation) metrics: Profiler fps = rendered; GetFpsGenerated counts FFX frameGenerationCallback calls (RHI_FrameGeneration::GetGeneratedFrameCount), GetFpsPresented = sum. profiler_snapshot/engine_status expose fps_generated, fps_presented, frame_generation, input_latency_ms, frame_generation_latency_ms. Latency adds an estimated hold of half a rendered interval (500/fps ms) while generating, interpolation GPU time not included, DXGI stats skipped on the proxy swapchain. Timer limiter paces displayed frames (presents_per_frame=2 while generating, so 240 Hz match = 120 rendered). With FG on, queue_present CPU block absorbs FFX pacing (~7 ms), that is waiting, not work. screenshot_take never shows generated frames.
- Car controls live only in the editor Controls window (GeneralWindows.cpp car_controls); the user removed the top-left DrawString cheat sheets from Car.cpp, do not add on-screen control text back. Keep car_controls in sync with Car::TickInput bindings.

## Car paint
- Car paint lives in g_buffer.hlsl (flake id + orange peel), brdf.hlsl BRDF_Specular_Flakes, light.hlsl (coat attenuates base specular), light_image_based.hlsl (ambient flake term). Material flag bit 25 = PaintPreset > 0 (gates orange peel without flakes). For materials with flakes, gbuffer material.b packs 0 aggregate lobe, 1..220 flake id (4 footprint levels x 55), 224..255 decal coverage; always read decal coverage through gbuffer_decal_coverage(). FlakeScale is flakes per UV unit; the LaFerrari body is ~10 m per UV unit so it needs ~12000 (presets use 12000), 160 gives centimetre speckles. When other agents leave the tree uncompilable or shaders out of sync with every exe: build in a git worktree at HEAD plus your diff (copy untracked Spartan.vcxproj, junction third_party and worktree binaries/data + binaries/project to the main copies, copy binaries/*.dll), then headless_start with the absolute exe path. Shaders resolve by walking up from the exe dir; the exe chdirs to its own dir and logs there, so headless_start's log_tail (binaries/log_headless.txt) is stale. Remove junctions with rmdir (no /s) before git worktree remove. cvar_set value must be a string.

## Terrain pads
- Live pads (TerrainSnap.cpp) measure the whole building: find_snap_platform grows over floor-like meshes (bottom within 2 m of seed) under the assembly root (highest ancestor below a world_layer/location_root tag). Height = min(max bottom of 0.2-1.5 m slabs not resting on another member, min mid-thickness) + sink min(0.04, thickness/4). After each load RefitPlatformsToOwners re-measures single-owner pads once and replaces one only if a grounded slab floats >0.15 m; terraced pads (villa 9046*, stone terraces 9017*) are left alone. Refit is live only, persist with world_save. Probe pad ground with world_raycast from ABOVE pad height (refine sits at pad+0.02, often inside the slab); rays from below read the coarse tile 0.3-0.5 m low. Ground under sidewalks at bed level is hidden by the deck, not a gap. Never pipe MSBuild through Select-String/Select -First (hangs holding the PCH); log to a file with /nodeReuse:false. Other agents' headless_start can retarget both spartan_engine namespaces; check spartan_status first.

## Secondary views (Tree Creator / Asset Viewer previews)
- Preview renders first each frame with its own target set (`secondary_render_targets`, freed after 120 idle frames) and frame slot main+4; a boundary submit waits on its compute timeline before the main view. World targets always come from the main set (`is_world_render_target`); view state swaps via `swap_view_state`. Passes iterating lights must use `GetViewLightEntities()`, preview lights are inactive in the world tick and need `Light::UpdateMatrices()` refits. Near directional cascade is per light (`Light::SetCascadeNearExtent`, default 64 m), `preview_rig::place_camera` fits it to camera distance + radius; the preview fill light casts no shadows. Isolation check: main screenshot, orbit with `tree_preview_capture {yaw, zoom}`, screenshot again, `screenshot_compare {a, b, threshold:16}`; wind noise is ~6-8% / mean ~3. Take baselines after the scene settles. `tool_batch` does not forward `args` to `engine_command` steps.
