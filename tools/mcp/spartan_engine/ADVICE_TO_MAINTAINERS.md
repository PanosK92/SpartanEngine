# Advice To Maintainers

What the AI agents working on Spartan Engine ask the maintainers to fix. One line per item: where it happens, what goes wrong or is missing, and what would fix it. Agents add items with `advice_to_maintainers_append` and remove the ones they have verified as fixed with `advice_to_maintainers_resolve`. This is not agent memory: no how-tos, no lessons, no session notes.

## Bugs
- A second `world_load` in one engine session blows up GPU memory, so every world switch needs an engine restart.
- A second play mode entry in one session has hit VK_ERROR_DEVICE_LOST during car renders.
- 2026-10-12 game.world: `terrain_scatter_set` on a mesh layer rescatters 25.8M instances and has killed the engine with VK_ERROR_DEVICE_LOST. Wanted: a bounded or staged rescatter.
- 2026-10-17 The first `screenshot_take` after a world load or thumbnail work is black.
- 2026-10-17 `compound_create`: some new parts never render until they are cloned and the original deleted (not reproduced on 2026-11-12 with box and revolved parts).
- 2026-11-08 `material_semantic_create` and other generators move a requested `path` outside the generated resources into blockout/materials/<name>.xml; the receipt now reports it as `path_rewritten`. Wanted: decide whether a library path should be honored.
- 2026-11-06 Pausing the sequencer releases the cars and shows the HUD, so a shot can only be frozen with `engine_set_mode` pause; drive event cars cannot start mid-take, `sequencer_playback {time}` only seeks the camera timeline.
- A pending `asset_viewer_screenshot` can block `screenshot_take`.
- Static collision and raycasts only exist within 40-80 m of the active camera: entering play with the camera far from a car drops the car through the floor, and `world_raycast` misses distant ground.
- ModelImporter reuses `<model_dir>/<material>.xml` and its cached packed textures, so changed GLB textures do not show until the xml is deleted and the engine restarted.
- Exploratory Lua (API probing, `pairs()` on raw containers) has crashed the engine. Wanted: bindings that raise an error. Ids already pass as strings (`entity:GetObjectID()`, `World.GetEntityById`).
- `world_save` after play has crashed in `Render::UpdateLodIndices` on a freed car Mesh (probably the freed mesh bug fixed 2026-10-19, unverified).
- The GeometryInfo storage buffer is rewritten at offset 0 on every TLAS rebuild while older frames may still read it.
- ReSTIR hit shaders do not apply puddles; ReSTIR direct lacks cloud shadows, ocean transmission and grass contact shadows outside the TLAS.
- 2026-11-12 Shader hot reload: while a compute PSO recompiles (about 10 s after the shader itself) its pass is skipped, e.g. the water composite goes black. Wanted: keep the old pipeline until the new one is ready.
- 2026-11-12 Ocean contact foam searches the opaque depth on screen, so an object whose waterline is hidden (looking down on a capped pile) gets none. Wanted: a world space source such as a ray query or a distance field.
- 2026-11-13 `headless_smoke_test` fails Render.BasicCube on unmodified HEAD 890e9ee26 (development build of 2026-11-13 10:33): center RGB 0.244, 0.335, 0.152 where a finite green emissive cube is expected, 15/16 pass. Either the fixture or the expectation is stale.
- 2026-11-13 engine_wait {ms: N} returns after ~10 ms (until=ready) in play mode instead of waiting N ms, so timed sampling of physics silently collapses into a few frames. Workaround: screenshot_take with wait_ms between samples. Either honor ms or document that until=ready wins.
- 2026-11-13 Physics friction_rolling is passed to physx as dynamic friction (Physics.cpp createMaterial(m_friction, m_friction_rolling, ...) and setDynamicFriction(m_friction_rolling)), while the property metadata calls it rolling friction. With the 0.4 default a box with friction 0.9 slides down a 25 degree ramp as soon as it moves. Rename it to dynamic_friction (or derive it from friction) and fix the metadata.
- 2026-11-13 entity_clone of a Text3D entity, then component_set of its text: the clone keeps showing the source text and the log says 'Text3D::GenerateMesh: 3d text requires an entity without an existing mesh'. Only world_save + world_load regenerates it. Fix: let Text3D replace its own generated mesh when the text changes on a cloned entity.
- 2026-11-15 vehicle_validate cannot run: tools/mcp/spartan_engine/vehicle_validation.mjs calls tools/car_validation/build.ps1 and references.json, and the README links tools/car_validation/README.md and telemetry.md, but tools/car_validation does not exist and never was in git history. Either commit the harness or remove the tool and the README section. Handling work currently has to use vehicle_maneuver telemetry on a live instance instead.
- 2026-11-15 world_save (World::SaveToFileInternal cleanup) deletes owned files in <world>_resources that no live component references at save time. A save of game.world from a headless instance at the garage removed 147 files, many named after terrain scatter variants (fern_a, lentisk_a, stump_a... meshes, their textures and materials); whether the engine can rebuild those from the gltf sources was not tested, the files were restored from a copy. The directory is git ignored, so nothing else brings them back. Fix: treat terrain scatter mesh_path/mesh_variants and prefab contents as references, or move pruning out of save into world_resources_clean with a dry_run that lists files first.
- 2026-11-15 world_save adds a new suffix generation of scatter variant resources: saving game.world again after copying back the files the previous save pruned wrote 140 new files (foo_4.xml/.mesh/.texture next to foo and foo_3) and 140 new Resource rows (2611 -> 2751). HEAD already has foo plus foo_3 pairs. A save should reuse an owned resource with identical content, and the prune should not delete files a saved Resource row still names.
- 2026-11-16 cvar r.screenshot_exr 1 writes no EXR: save_screenshot_async (Renderer.cpp) ignores exr_staging and only saves the tonemapped PNG, so absolute luminance calibration has to invert the GT7 curve at a fixed manual EV. Wanted: write the linear HDR frame (or add screenshot_take {hdr: true}) in cd/m2.
- 2026-11-21 material_textured_create materials created with procedural textures can stay in state 2 (Loading) and render completely invisible after world_save + world_load (observed across 7 materials in ferrari_showroom_example.world, while material_create PBR materials in state 3 persisted cleanly). Fix: finalize packed texture creation and transition material_textured_create resources to Ready before returning, and ensure world_save/world_load resolves their packed textures reliably.

## UX Improvements
- No MCP tool closes a visible engine instance (`engine_quit` only closes headless ones); agents fall back to WM_CLOSE.
- No MCP tool clicks editor UI and `input_inject` keys never reach ImGui widgets: popups, the Terrain Sculpt brush and the Memory Viewer CSV export need the user.
- No MCP capture of the full audio mix; `engine_sound_capture` records only the engine synth.
- No camera follow for a moving car.
- New dedicated tools appear only after Cursor respawns the MCP server. Wanted: register new tools without a respawn.
- 2026-11-12 data/shaders is shared by every running instance: `shader_reload` without `name` recompiles everything another agent touched (about 160 shaders and 90 s after a common.hlsl edit) and pulls their half finished work into your instance. Wanted: a shader directory per instance, or reload only what this session changed.
- 2026-11-06 A road `shader_reload` takes about 4 minutes headless.
- Visible instances share binaries/logs/log.txt and settings/editor.ini. Wanted: one per instance.
- A minimized engine window stops rendering, GPU timings and screenshots. Wanted: keep rendering while an MCP session is attached.
- An editor window moved past the editor edge becomes a separate OS window that `screenshot_take {ui: true}` does not capture.
- 2026-11-06 Guide splines made with `spline_create_road` (mesh off) are live only and must be recreated after every reload.
- `texture_generate` at a loaded path writes the next free suffix (reported in `requested_path`) instead of overwriting and reloading the texture, and material `color_r/g/b` can only darken a surface.
- 2026-11-13 `shader_reload {name: "imgui"}` matches 0: the editor UI shader (data/shaders/imgui.hlsl, owned by ImGui_RHI.h) is outside the renderer's shader registry, so a UI shader edit needs an editor restart. Wanted: include it in hot reload.
- 2026-11-13 No MCP control for output resolution, render resolution or the fps limit (Renderer::SetResolutionOutput/Render, Timer::SetFpsLimit are not cvars), so an agent cannot measure what matching the output to the viewport saves or throttle an idle instance. Wanted: a session-only tool or cvars for them. `profiler_record` also has no dedicated tool, it is only reachable through `engine_command`.
- 2026-11-13 `window_restore` has no counterpart: an agent that restores a window the user had minimized cannot minimize it again when done, so the instance keeps rendering at full GPU load. Wanted: `window_minimize`, or have `window_restore` return a token that restores the previous state.
- 2026-11-13 component_get on text_3d lists a generate_mesh action, but component_action rejects it for text_3d, so there is no way to force the text mesh after an edit; it only appears after the internal debounce. Accept the listed action, or stop advertising it. Separately, screenshot_take caps wait_ms at 10000 and console_read returns PSO compile spam regardless of filter, which buries script errors.
- 2026-11-13 Headless play testing of click gameplay: World.GetCursorRay() returns a stale ray because there is no real cursor, so a script that picks under the cursor cannot be clicked unless the test holds Click_Right to force its centred ray. Script Hud text is also missing from screenshot_take. Fix: let input_inject take a viewport cursor position that feeds GetCursorRay, and composite the Hud into MCP screenshots (or add an option).
- 2026-11-15 The workflow rules tell agents to call agent_memory_read at session start and agent_memory_append at the end, but the server exposes neither tool (only advice_to_maintainers_*). AGENT_MEMORY.md can be read as a file, but there is no sanctioned way to append a lesson. Add the two tools or change the rule to say the file is edited directly. Also vehicle telemetry csv has no self aligning torque or rack force column, which steering feel work needs.
- 2026-11-15 viewpoint_capture accepts unknown arguments (additionalProperties), so `name: "x"` instead of `names: ["x"]` silently shoots every saved viewpoint (40 in game.world, ~440 MB of png per pass). Inside a tool_batch three such steps exceeded the MCP request timeout and kept running after the error was returned. Fix: reject unknown arguments on this tool (or accept `name`), and have tool_batch stop its remaining steps when the client request times out.
- 2026-11-15 Shader iteration through the bridge: engine_wait until "ready" returns while shader_reload is still compiling (engine_status shaders_compiling stays 0 for a scoped reload), so the only way to learn compiling/failed is a second shader_reload with a name that matches nothing. Add until "shaders" that waits for the reload and returns failed shaders with their errors. Also console_read and cvar_list ignore their filter arguments and return the whole log / every cvar (hundreds of KB).
- 2026-11-15 cvar r.debug_view (show a render target) has no effect on viewpoint_capture / screenshot_take in a headless instance, so an agent cannot look at albedo, light_diffuse or ssao. A buffer argument on screenshot_take would make lighting bugs (grass blades 20 to 50 times darker than the ground they grow on) diagnosable without shader edits.
- 2026-11-16 cvar_set r.ssao 1 silently returns value 0 while r.restir_pt is on (on_ssao_change resets it), and r.debug_view is not visible in screenshot_take (scene or ui) even on a windowed instance, so an AO-only capture is impossible via the bridge. Fix: return a reason in cvar_set when a change callback reverts the value, and make screenshot_take honour r.debug_view (or add a render target capture tool).
