- [Engine Facts] Engine MCP commands run on the engine main thread at the start of the frame; request ids are echoed in responses and debug logs. Mutating scene tools require edit mode.
- [Engine Facts] `engine_command {command, args}` forwards any native bridge command. Use it for commands added to the engine after the MCP server started, or args a dedicated tool lacks. Tool inputs pass unknown args through, so an older server no longer strips new engine args. New dedicated tools still appear only after Cursor respawns the server: change its env (e.g. SPARTAN_MCP_REVISION) in ~/.cursor/mcp.json.
- [Engine Facts] `shader_reload` hot reloads shaders: it recompiles every shader whose .hlsl or include differs on disk from what it was compiled from (`name` filters, `force` recompiles matches). Compiles run in the background; call again until `compiling` is 0, then check `failed` and `console_read`. Edit the repo's data/shaders (binaries/data/shaders is setup's fallback copy, not what runs).
- [Engine Facts] `component_get` exposes properties, raw members and metadata (ranges, units, enums, side effects); `component_set`/`component_set_batch` write them, `component_action` runs component methods (terrain generate, spline road mesh, particle presets, light fit_to_mesh...).
- [Engine Facts] `terrain_scatter_get` / `terrain_scatter_set {layer, values}` read and edit terrain scatter layers (vegetation, rocks, grass) with the world file's <layer> attribute names. Grass/detail update instantly; mesh layers rescatter in the background (poll `mesh_rescatter_running`) and every mesh layer re-rolls.
- [Engine Facts] Resources: `resource_list/load/reload/save/remove`, `material_get`, `material_create`. `world_save` prunes unreferenced files from the world resources directory; `world_resources_clean` returns a receipt.
